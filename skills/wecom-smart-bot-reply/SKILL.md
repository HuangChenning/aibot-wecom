# 企业微信智能机器人回传

将已经完成的内容投递回**发起该任务的企业微信智能机器人会话**。本 skill 是出站回传层：它不接收企业微信消息、不创建机器人、也不自行启动新的 WebSocket。

## 进入条件

仅在下列条件都满足时回传：

- 当前任务由企业微信智能机器人入口触发，且调用方提供了不透明的 `replyContext`；
- 本机已有保持该机器人 WebSocket 连接的 relay 常驻进程（`wecom-aibot serve`），且 `wecom-aibot status` 返回退出码 `0`；
- 需要回传的内容已经最终确定。

缺少任一条件时，不要猜测聊天、用户或机器人；保留结果并说明缺少哪项集成条件。不得使用 `botId + secret` 临时新建连接来补救，这会丢失原消息的响应语义并可能造成重复发送。

## 回传流程

1. 读取调用方提供的 `replyContext`，将其视为仅能交给 relay 的不透明令牌；不得打印、拼接或修改其中的字段。
2. 先将结果整理成适合企微阅读的 Markdown：结论在前，保留必要链接，避免超宽表格和本地绝对路径。附件需求交由 relay 的媒体上传能力处理，不能把本地路径当作可访问链接发送。
3. 把最终 Markdown 写入一个 UTF-8 文件，再调用 relay CLI；正文只经文件传递，不放进命令行参数：

   ```bash
   wecom-aibot reply --context "$REPLY_CONTEXT" --content-file ./reply.md
   ```

4. 按退出码决定后续动作，不要解析 stdout 之外的内容：
   - `0` 已送达，停止。
   - `1` 明确未送达；只有在确认是本地 relay 未运行等临时问题时才在修复后重试一次。
   - `75` 结果未知；**停止重试**，向调用方说明需要人工核对，避免同一会话出现重复回复。

完整的边界、relay 契约、拆分与失败策略见 [长连接回传契约](references/relay-contract.md)。在接入或实现 relay 前，先阅读该文档。

## 内容规则

- 只回传本次调用者授权发送的内容。含凭据、访问令牌、内部路径、工具原始输出或其他会话信息时，先移除或概括。
- 当前 relay 只投递最终消息：同一个 `replyContext` 送达一次后即终止，重复调用返回同一结果，不会产生第二条消息。
- 内容过长时 relay 会返回明确未送达（退出码 `1`）。此时压缩内容后可再试一次；不要自行假定固定的企业微信长度上限，也不要拆成多条消息发送。
- relay 明确拒绝 Markdown 时，降级为纯文本；附件或媒体被拒绝时说明失败，不重复上传或伪造链接。

## 不适用范围

- 企业微信自建应用的 HTTP 回调、群机器人 webhook、或没有原始会话上下文的主动通知；它们需要各自的发送能力。
- 需要接收消息、维护 WebSocket 重连、鉴权或处理回调确认的任务；这些属于 relay 宿主。
